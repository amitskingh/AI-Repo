# 4 – Dataclasses

Dataclasses (Python 3.7+) cut boilerplate for classes whose main job is storing data. Pydantic, FastAPI, and many AI libraries follow the same idea: clean data models make apps easier to build.

## The problem

```python
class User:
    def __init__(self, name: str, age: int, city: str):
        self.name = name
        self.age = age
        self.city = city
```

Add `__repr__`, `__eq__`, hashing, ordering, immutability—and every data model repeats the same noise. Dataclasses automate that. A dataclass is still a normal class; Python just generates common methods for you.

## Basic syntax

```python
from dataclasses import dataclass


@dataclass
class User:
    name: str
    age: int
    city: str
```

By default you get `__init__`, `__repr__`, and `__eq__`:

```python
user = User("Harvey", 28, "Mumbai")
print(user)  # User(name='Harvey', age=28, city='Mumbai')

User("A", 20, "Delhi") == User("A", 20, "Delhi")  # True
```

## `field()` and `default_factory`

```python
@dataclass
class ChatSession:
    history: list[str] = []  # WRONG — one shared list for all instances
```

Mutable defaults are evaluated once at class definition. Use:

```python
from dataclasses import field


@dataclass
class ChatSession:
    history: list[str] = field(default_factory=list)
```

Each instance gets its own list. This is a frequent interview topic.

## When to use which

| Use a dataclass when… | Use a normal class when… |
|------------------------|---------------------------|
| Primary job is storing data | Behavior / business logic dominates |
| You want less boilerplate | Complex validation or state machines |
| Equality should follow field values | Heavy inheritance or significant methods |

**Dataclass examples:** Message, User, ChatResponse, EmbeddingResult  
**Normal class examples:** ChatBot, Retriever, DatabaseConnection

## Common mistakes

Never use `history = []` (or `history: list[str] = []`) on a dataclass unless you want shared mutable state. Use `field(default_factory=list)`.

## AI / LangChain connection

Structured results (documents, messages, tool outputs, config) are often dataclasses or Pydantic models—same idea: represent data cleanly.

```python
@tool
def search(query: str) -> SearchResult: ...
```

## Interview questions

- What problem do dataclasses solve?
- Which methods are generated by default?
- Explain `default_factory`. Why is `history=[]` dangerous?
- When would you choose a dataclass over a normal class?

## Summary

Dataclasses reduce boilerplate for data-centric classes. Use them for data; use normal classes for behavior. Always use `default_factory` for mutable defaults.
