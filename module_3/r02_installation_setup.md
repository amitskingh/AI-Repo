# 2 – LangChain Installation & Project Setup

## Project Setup

Recommended initial structure:

```text
langchain-learning/
│
├── .venv/
├── .env
├── .gitignore
├── requirements.txt
│
└── module_2/
    └── lesson_2_2/
        └── main.py
```

## Create the Project

```bash
mkdir langchain-learning
cd langchain-learning
```

## Create a Virtual Environment

```bash
python -m venv .venv
```

Activate it.

#### Linux / macOS

```bash
source .venv/bin/activate
```

#### Windows

```powershell
.venv\Scripts\activate
```

After activation, the terminal should show something similar to:

```text
(.venv)
```

## Why Use a Virtual Environment?

A virtual environment isolates project dependencies.

Without virtual environments:

```text
System Python
    │
    ├── Project A
    │
    └── Project B
```

Different projects can require conflicting package versions.

With virtual environments:

```text
System Python
    │
    ├── Project A
    │      └── .venv
    │
    └── Project B
           └── .venv
```

Each project can maintain its own dependencies.

## Upgrade pip

```bash
python -m pip install --upgrade pip
```

Using:

```bash
python -m pip
```

helps ensure that pip is associated with the Python interpreter/environment currently being used.

## Install LangChain

```bash
pip install langchain
```

This installs the main LangChain framework.

## Install the Model Provider Integration

For OpenAI:

```bash
pip install langchain-openai
```

The packages have different responsibilities:

```text
langchain
    ↓
Core LangChain framework

langchain-openai
    ↓
OpenAI integration
```

LangChain separates many provider integrations into their own packages.

## Environment Variables

Install `python-dotenv`:

```bash
pip install python-dotenv
```

Create:

```text
.env
```

Example:

```env
OPENAI_API_KEY=your_api_key_here
```

## Why Use `.env`?

Do NOT put secrets directly in source code.

#### Bad

```python
api_key = "sk-xxxxxxxx"
```

#### Better

```text
.env
   ↓
Environment Variable
   ↓
Application
```

This keeps secrets outside the source code.

## `.gitignore`

Never commit the `.env` file.

Example:

```text
.env
.venv/
__pycache__/
```

This prevents sensitive information and local environment files from being committed.

## Requirements File

Create:

```text
requirements.txt
```

Initially:

```text
langchain
langchain-openai
python-dotenv
```

Install everything using:

```bash
pip install -r requirements.txt
```

For production, dependencies should generally be pinned and tested for compatibility.

## First LangChain Program

Create:

```text
module_2/lesson_2_2/main.py
```

```python
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI

load_dotenv()

model = ChatOpenAI(
    model="gpt-4.1-mini",
)

response = model.invoke("Explain what an embedding is in one sentence.")

print(response.content)
```

Run:

```bash
python module_2/lesson_2_2/main.py
```

## Understanding the Code

### `load_dotenv()`

```python
load_dotenv()
```

Loads variables from `.env` into the application's environment.

### `ChatOpenAI`

```python
from langchain_openai import ChatOpenAI
```

This is LangChain's OpenAI chat-model integration.

### Create the Model

```python
model = ChatOpenAI(
    model="gpt-4.1-mini",
)
```

This creates a LangChain chat model object configured to use the specified model.

### Invoke the Model

```python
response = model.invoke("Explain what an embedding is.")
```

`invoke()` means:

> **Execute this LangChain component with the given input and return the result.**

We will study the Runnable interface later.

## What Is `AIMessage`?

A chat model generally does not return only a plain string.

It returns an AI message object.

Conceptually:

```text
response
   ↓
AIMessage
   ├── content
   ├── response metadata
   └── additional information
```

Therefore:

```python
print(response)
```

may display more information than just the generated text.

To get the actual generated content:

```python
print(response.content)
```

## AIMessage role

You will encounter:

```text
AIMessage
```

It represents a message generated by the AI model.

Later we will work with:

```text
SystemMessage
HumanMessage
AIMessage
ToolMessage
```

These will be covered in **Module 2.4 – Messages**.

## What Is `ChatOpenAI`?

```python
model = ChatOpenAI(...)
```

`ChatOpenAI` is a LangChain integration for OpenAI chat models.

Conceptually:

```text
ChatOpenAI
    ↓
LangChain Integration
    ↓
OpenAI API
    ↓
Chat Model
```

## Why Provider-Specific Packages?

Modern LangChain separates many model integrations.

For example:

```text
langchain-openai
langchain-anthropic
langchain-google-genai
```

This keeps provider integrations separate from the main framework.

## Temperature

Temperature was covered in Module 1.

It can be configured when creating the model:

```python
model = ChatOpenAI(
    model="gpt-4.1-mini",
    temperature=0,
)
```

A lower temperature can be useful for tasks where less sampling variability is desired.

However:

> Lower temperature does not universally guarantee perfectly deterministic behavior.

The exact behavior depends on the model/provider implementation.

## Common Setup Problems

### `ModuleNotFoundError`

Example:

```text
ModuleNotFoundError:
No module named 'langchain_openai'
```

Check that the correct environment is active:

```bash
pip list
```

or:

```bash
python -m pip show langchain-openai
```

### API Key Error

Check:

```text
.env
```

and:

```python
load_dotenv()
```

Also verify that the API key is valid and that the application is using the intended environment.

### Wrong Python Environment

Linux / macOS:

```bash
which python
```

Windows:

```powershell
where python
```

The result should point to the intended virtual environment.

## API Key Security

Never:

```python
print(os.getenv("OPENAI_API_KEY"))
```

in production logs.

Never commit:

```text
.env
```

Never expose API keys in:

```text
Frontend JavaScript
React Application
Browser Code
Public GitHub Repository
```

Provider API keys should remain on the server/application side.

### Direct Provider SDK



LangChain is useful when its abstractions help with composition and orchestration.

## Best Practices

#### Always use a virtual environment

Avoid installing project dependencies globally.

#### Keep secrets outside source code

Use environment variables or a proper secrets manager.

#### Keep provider integrations separate

Install only the integrations required by the application.

#### Understand the underlying provider API

Don't treat LangChain as a black box.

Know:

```text
Input
 ↓
Model
 ↓
Response
```

before relying heavily on abstractions.

#### Inspect model responses

During development:

```python
print(response)
```

can be useful to understand the complete message object.

When only generated text is required:

```python
print(response.content)
```

#### Don't blindly copy versions from old tutorials

LangChain changes relatively quickly.

Prefer current package documentation and compatible versions.
